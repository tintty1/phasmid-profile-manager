# Changelog

All notable changes to this project are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

History before the fork is in the upstream project,
[camoufox-profile-manager](https://github.com/polyackiy/camoufox-profile-manager)
(imported at `d1f2815`).

## [Unreleased] - 0.1.0

The port of camoufox-profile-manager from Camoufox (Firefox via Playwright) to
Phasmid (Chromium), driven over CDP.

### Added
- *Copy CDP URL* in the browser viewer's toolbar, beside the one in a profile's
  menu. Copying falls back to `execCommand` when the UI is served over plain
  http (no `navigator.clipboard`), and shows the URL to copy by hand if that
  fails too.
- Per-profile downloads: each profile saves into `<data dir>/downloads/<id>/`,
  listed, fetched and deleted with
  `GET|DELETE /api/v1/profiles/{id}/downloads[/{name}]`, and shown in the web
  UI (*Downloads…* in a profile's menu). Downloads a person starts go there
  through the profile's preferences; the CDP relay redirects the ones a client
  starts there too, names them without overwriting, and lets a client find one
  by GUID (`?guid=`). The skill's `save_download()` uses that.
- `copy_data` on clone (default true): false copies the settings and proxy but
  not the browser data. In the UI, *Duplicate without data*.
- A profile's machine is a full Phasmid profile JSON, generated by the
  `phasmid-profile-gen` package (run in a child process) from one capture of a
  real device, and stored on the profile. `GET /api/v1/profiles/{id}/machine`
  returns it; the profile response carries a summary.
- Machine settings: `os` (`linux` or `windows`), `gpu`
  (`<vendor_id>:<device_id>`, listed by `GET /api/v1/fingerprints/gpus`),
  `languages`, `timezone` and `webrtc_policy`.
- Every launch looks up the exit address through the profile's proxy. When it
  moved, phasmid-profile-gen regenerates the machine from the same seed and only the
  location group (`locale`, `network.webrtc.public_ip`) is taken; the hardware
  is copied from the pin. A proxied launch whose proxy does not answer is
  refused.
- The browser is a process the manager starts itself, with `--phasmid-profile`,
  `--user-data-dir` and `--remote-debugging-port=0`, in a process session of its
  own. Proxies go through Phasmid's `tools/proxyroute`, with credentials in a
  0600 file rather than on the command line.
- `cdp_endpoint` in the launch response and the authenticated CDP relay
  `WS /api/v1/profiles/{id}/cdp`, for Playwright's `connect_over_cdp`,
  Puppeteer and other CDP clients.
- `args` on the launch request: extra Chrome switches.
- *Install browser* downloads the newest Phasmid release with a Linux x64 build
  from `PPM_PHASMID_REPO`, verifies its `.sha256`, unpacks it, and fetches the
  source tree at the tag (for `tools/proxyroute`) and the DB-IP database
  phasmid-profile-gen pins.
  `PPM_PHASMID_RELEASE` pins a tag; `PPM_PHASMID_BINARY` and
  `PPM_PHASMID_SOURCE` use a local build and checkout.
- Browsers left running by an instance that died are closed at startup.
- *View machine JSON* and *Copy CDP URL* in the web UI.
- Docker: Chrome's runtime libraries, Phasmid's Linux font families,
  `seccomp:unconfined`, and uid 1000; the browser and the DB-IP cache live in
  the `/data` volume.
- The agent skill drives profiles with `connect_over_cdp`.

### Changed
- Package `camoufox_pm` is now `phasmid_profile_manager`, the command
  `camoufox-pm` is now `phasmid-profile-manager` (alias `phasmid-pm`, or
  `python -m phasmid_profile_manager`), and the environment prefix `CPM_` is
  now `PPM_`. Published to PyPI as `phasmid-profile-manager`.
- Requires Python 3.12 or newer (phasmid-profile-gen needs it). CI runs 3.12 and 3.13.
- New profiles default to Linux.
- Schedules have one action, `launch`.
- Modals stack, so Escape closes only the top one.

### Removed
- Camoufox, Playwright-launched Firefox, `playwright_endpoint` and the
  `/profiles/{id}/playwright` relay.
- Device presets (`fingerprint_preset`, `GET /fingerprints/presets`); a GPU is
  now chosen among captured hosts.
- The browser-version refresh: its endpoint, its schedule action and the
  *Update* button. Phasmid reports the version it was built from.
- The Firefox-only settings (screen, window size, user agent, locale,
  geolocation, CPU and memory values, touch points, fonts, noise toggles,
  stable canvas, WebRTC modes and addresses, browser interface theme) and the
  flattened `browser_*` update fields.
- `browser_session_id` and `camoufox_options` in the launch response.
- The Chrome-to-Firefox migration extra.
- macOS and Windows desktop installers, their build script and workflow, and
  code signing.
- The Russian translations and the screenshots of the Camoufox UI.
